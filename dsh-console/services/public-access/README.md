# 微信管理员与兑换码服务

提供网页管理台、微信管理员绑定、账号公网兑换码和中继鉴权。正常部署及原机升级请先看 [统一部署教程](../../deploy/README.md)；本文件说明权限边界与兼容协议。

兑换码只开通本平台的公网服务：用户连接自己的 DSH，局域网、直接连接、自建中继不依赖本服务。旧版「限时配对 / 生成配对码」保留为可选托管功能，它限制设备凭据，与公网兑换时长分开；不要为了开通公网安装限时网关扩展。

## 当前边界

本仓库新版 relay 已接入账号级鉴权：小程序微信登录后取临时公网票据，relay 使用私有共享密钥向本服务验证账号、节点和手机设备；连接到期断开，并每 30 秒复查账号状态。票据最多 24 小时且不超过账号有效期。管理员当前免兑换，移除管理员后按账号有效期处理。上线需同时升级服务器、小程序及插件内置连接器，并进行真机验收；不代表代码已部署到你的服务器。

Node.js 22+，二维码使用 qrcode，核心身份 API 使用 Node 内置库，仅支持单实例写入状态文件。并发请求在同一进程内原子占用次数；不能让多个进程或服务器共用该 JSON 文件。正式扩容必须改为数据库事务。

## 部署配置（仅服务端）

新部署优先用仓库 deploy 目录初始化。必须配置 CONSOLE_ORIGIN、ACCESS_MASTER_KEY、CONSOLE_SETUP_TOKEN；AppID、管理员在网页管理。新账号码不需要节点或授权接口。下列环境变量并非全部必填。

- WECHAT_APP_ID / WECHAT_APP_SECRET：小程序凭据，Secret 绝不能打包进小程序。
- ADMIN_OPENIDS：绑定微信公众平台管理员本人在本小程序 AppID 下的 OpenID，逗号分隔。不能使用昵称、微信号、其他小程序的 OpenID、客户端传入角色或首个登录用户。
- MANAGED_NODE_IDS：仅旧节点绑定码使用的节点 UUID，逗号分隔。
- ACCESS_STATE_FILE：私有状态文件的绝对路径；定期备份，勿放静态站点或 Git。
- ACCESS_HOST / ACCESS_PORT：默认 127.0.0.1:8790，置于固定 HTTPS 反向代理后。
- RELAY_AUTH_SECRET：本服务和 relay 共用的内部鉴权密钥，统一部署自动生成。不能发给用户或放到小程序。
- ACCESS_GRANT_URL / ACCESS_GRANT_TOKEN：仅旧节点绑定码需要的外部授权适配器。缺少时只拒绝旧节点码，新账号公网码正常生成和兑换。

独立部署 relay 时需要 RELAY_REQUIRE_PUBLIC_ACCESS=true、RELAY_AUTH_URL 指向此服务私网的 /internal/relay/authorize，以及同一 RELAY_AUTH_SECRET。内部接口不能暴露公网；统一部署 Caddy 已屏蔽 /internal/*。不开启强制鉴权的旧独立 relay 不会执行此账号有效期，不能只部署网页就视为公网限制生效。

进入本服务目录，先运行 npm ci --omit=dev，再运行 node --env-file=.env server.cjs。Docker / HTTPS 完整配置见 README-deploy.md。

将固定 HTTPS 域名加入微信后台 request 合法域名，并填写 utils/access-config.js 的 baseUrl。对应 WSS 域名加入 socket 合法域名，不带 /relay 路径。不要关闭 TLS 校验。网关插件的 `notificationServiceUrl` 也必须指向同一个公网服务（默认 `https://dsh.ahwe.top`）；自托管时需在 DSH 网关配置中改成自己的 HTTPS 服务地址并重启插件。小程序编译已排除 services、tests、deploy 和 relay 目录。

任务完成提醒使用与小程序内置 ID 相同的「任务完成提醒」模板；模板需已添加到该 AppID 下的「订阅消息 → 我的模板」。**模板 ID 只在小程序端配置**（`miniprogram/utils/notify-config.js`），小程序申请票据时随请求提交 `templateId`，服务端按票据携带的模板 ID 发送；服务端内置默认值仅用于兼容未提交模板 ID 的旧版小程序。修改模板时只改小程序端即可。设置开关只保存偏好；用户发送任务时小程序请求微信一次性订阅授权，只有用户接受后才向此服务申请限时票据。票据摘要持久化保存、3 天过期，网关在对应 DSH 回合结束后回调 `/notifications/complete`；回调幂等且绑定到该会话，服务重启后可继续处理未完成票据。后台通过服务端 AppSecret 调用微信 `subscribeMessage/send`。通知不包含任务正文或模型回复；此接口依赖新版小程序、网关插件与本服务同时部署，旧版网关不会发送完成回调。

### 自定义通知模板字段

微信公众号订阅消息的关键词标签由微信固定，不可自定义。因此时长和缓存命中率组合进「任务结果」或「备注」字段的值里，指标名自带在值字符串中。

网关回调 `/notifications/complete` 时可附带 `taskName`、`durationMs`、`tokens`、`cacheHitRate`。**模板想显示真实任务数据时，网关必须实际提交这些字段**；服务端无法从票据或会话 ID 推算耗时、Token 或缓存命中率。服务端根据模板内容中的关键词自动匹配字段并填充真实值。旧网关或未提交指标时会发送通用占位值，其中 number 类型使用 `0`，不会伪显示成消耗了 1 个 Token。

推荐的关键词选择与指标映射：

| 指标 | 微信关键词 | 字段类型 | 显示效果 |
|------|-----------|---------|---------|
| 任务名称 | 任务名称 | thing | `重构通知模块` |
| Token 消耗 | Token | character_string（若模板允许） | `12.3K` |
| 任务时长 + 缓存命中率 | 任务结果（或备注） | thing | `时长2m30s · 缓存命中85%` |
| 完成时间 | 完成时间 | time | `2026-10-21 18:00` |

通知显示效果：
```
任务完成

任务名称：重构通知模块
Token：12.3K
任务结果：时长2m30s · 缓存命中85%
完成时间：2026-10-21 18:00
```

回调字段说明：
- `taskName`（字符串，最长 200 字符）：任务名称
- `durationMs`（非负数字）：任务时长（毫秒）
- `tokens`（非负数字）：Token 消耗量
- `cacheHitRate`（0–1 之间的数字）：缓存命中率

示例回调体：
```json
{
  "ticket": "...",
  "sessionId": "...",
  "status": "completed",
  "taskName": "重构通知模块",
  "durationMs": 150000,
  "tokens": 12345,
  "cacheHitRate": 0.85
}
```

在微信公众平台「订阅消息」中选用包含上述关键词的模板后，只需把模板 ID 更新到 `miniprogram/utils/notify-config.js` 的 `TEMPLATE_ID` 并重新发布小程序；服务端会使用票据中携带的模板 ID 发送（`notifications.cjs` 的 `DEFAULT_TEMPLATE_ID` 仅用于兼容未提交模板 ID 的旧版小程序）。

Token 字段若在微信模板中定义为 `number`，服务端会发送纯数字（如 `12345`）以满足微信校验；只有字段类型是 `character_string` 时才会格式化为 `12.3K`。模板关键词及字段类型由微信模板决定，不能由服务端覆盖。

## 自动识别管理员

设置页每次进入前台自动调用 wx.login，服务端使用本小程序凭据调用 code2Session 获取当前微信的 OpenID，再与网页已批准的管理员及 ADMIN_OPENIDS 严格匹配。命中才返回管理员，否则返回普通用户；不需要用户点击验证或切换身份。网络或配置异常时显示待识别并隐藏管理入口，不把失败当成已验证。

微信公众平台后台的管理员成员关系与本应用的业务角色不是同一个接口。code2Session 不返回微信号或管理员角色，本实现不宣称可以直接读取、自动同步公众平台管理员名单。本人在新版小程序「设置 → 公网访问」复制 WX- 开头的小程序设备 ID，由网页「微信与管理员」核实后绑定。ID 是服务端映射到已验证 OpenID 的账号标识，不是电脑节点或硬件 ID，24 小时内识别过才可绑定。普通用户不显示微信身份模块。更换管理员时网页移除旧身份并绑定新身份，即时生效；只有环境变量名单变更才需重启。旧版绑定码接口仅兼容旧客户端。

后台每次生成、查询、复制、停用、删除兑换码都独立校验管理员，客户端显示状态与本地缓存不能赋予权限。新版码加密保存，可跨端再次复制；旧版哈希无法恢复。删除阻止新兑换、保留已兑换时长及审计。不要在聊天、客户端配置或日志中发送 AppSecret。

## 分享活动

默认暂停，管理员在网页「分享活动」核对平台政策后启用、调整阶梯及审核朋友圈凭证。好友有效打开使用微信 OpenID 去重，不采信客户端设备 ID 或分享成功回调；同一微信全活动只计一次，自己打开不计奖。默认第 1–10 位每位 3 天、第 11–15 位每位 7 天、第 16 位起每位 30 天，不补发历史差额。默认朋友圈每个北京时间自然日一条、24 小时双截图人工审核通过后 3 天。

API：GET /share，POST /share/invite、/share/open、/share/moments/start、/share/moments/submit。普通请求上限 16KB；两个截图上传接口上限 470000 字节 JSON（解码图片上限 330KB）。网页管理接口 /console/api/share、/share/rules、/share/review、/share/proof/:id 受 Cookie/CSRF 保护，不允许小程序自行发奖。分享仅续期账号公网服务，LAN/节点权限完全独立。

截图审核后删除，未处理 7 天后清理；必要去重/奖励账本持久化。生产仍为单实例 JSON 状态存储，小规模可用；有较大流量须迁移数据库事务及私有对象存储，不要多实例共用状态文件。身份/奖励去重不等于防小号，截图不等于连续保留的技术证明。隐私、平台审核与两微信真机验收步骤见 deploy/README.md。

## 新账号公网码（默认方式）

管理员在网页或小程序生成不带 nodeId 的兑换码。普通用户先微信登录，再提交 /redemptions，后台把使用次数、兑换记录及账号到期时间一次性持久化；同账号重复提交同一码返回原结果，不重复续期。未到期叠加原时间，到期后从当前时间起算。

获取 /public-access/lease 时必须拥有有效公网时长。服务权限只决定能否用本平台中继；连接自己 DSH 仍需插件一次性配对码或有效设备凭据，通过端到端加密传输。后台不持有电脑设备配对密钥，也不会替用户自动配对。

历史 v1 状态升级为 v2 时保留原兑换记录、后台节点和管理员；已签发的旧节点码仍走旧协议。公网到期不会向电脑写入设备到期时间或撤销 LAN token。

## 旧节点码的授权适配协议（可选兼容）

只有旧节点绑定码使用下列合同；新账号公网码完全不调用它。原有 pending 兑换继续保留，不能因升级丢失已占用次数或重复授权。

POST ACCESS_GRANT_URL，服务端 Bearer token，Idempotency-Key 为 redemptionId。

请求 JSON 包含 redemptionId（UUID）、accountId（SHA-256(OpenID)）、nodeId（UUID）、durationMs（授权毫秒数）。

下游必须认证请求、校验节点归属、按账号与节点延长实际访问权限，持久化后返回 applied: true，以及原请求的 redemptionId、accountId、nodeId 和 expiresAt（毫秒时间戳）。

同一 redemptionId 重试必须返回同一结果，不得重复续期。公网客户端登录/握手和现有连接必须由该账号授权体系控制，到期后服务端撤销访问。当前网关设备 token 模式尚未接入，不自动改写它的有效期。

兑换先持久化占用次数，再调用适配接口；超时保留 pending，重试同一码沿用同一 ID。不能盲目释放 pending，避免下游已授权但响应丢失时超发。列表已用次数包括 pending 预留次数。

## 安全与操作

- 服务端通过微信 code2Session 获取 OpenID，每次管理请求核验白名单；不保存 session_key。
- 登录 token 随机生成，仅在服务端内存保存摘要，2 小时失效；重启需重新登录。
- 兑换码含 96 位随机量，数据库只存摘要；完整码仅生成时返回。每账号每码一次，同码重试幂等。
- 新账号码支持 3/7/30/180/365 天、1/5/20 人，码本身 30 天有效。旧节点码另保留 90 天兼容选项。停用不撤销已发授权。
- 网页管理员名单即时生效，环境变量名单变更后需重启。禁止记录 AppSecret、微信登录 code、完整兑换码或 token。
- 反向代理需配置 TLS、体积限制和逐 IP 限速；服务端不信任任意 X-Forwarded-For。
- 状态损坏拒绝启动，不清空原状态。此版本尚无数据库级备份、分布式锁或审计归档，不宜在缺少运维保障时作为收费授权平台直接上线。
