# 虚拟支付部署与验收手册（个人主体 · 工具类目）

> 配套：[接入契约](virtual-pay-contract.md)、[接入清单](virtual-payment-checklist.md)。
> 本手册覆盖「服务端环境变量 → MP 后台配置 → 小程序开关 → 真单验证 → 官方部署前检查清单逐项验收」。

---

## 0. 前置确认（不通过就先别部署）

| 检查项 | 在哪确认 | 通过标准 |
| --- | --- | --- |
| 主体 | MP 后台 → 设置 → 基本设置 | 个人主体，开发者持中国大陆居民身份证 |
| 服务类目 | MP 后台 → 设置 → 基本设置 → 服务类目 | 含「工具」；不含课程/内容/资讯；不涉及需电信业务资质的服务 |
| 认证 | MP 后台 → 设置 | 已认证 |
| 备案 | MP 后台 → 设置 → 备案 | 已完成 ICP 备案 |
| 月限额认知 | 官方文档 | 个人主体全终端月支付限额 10 万元，服务端已在 950 万/1000 万分处告警与拦单 |
| 费率认知 | 官方文档 | Android 等 1%（腾讯技术服务费）；iOS 12%（Apple 佣金） |

## 1. 服务端环境变量（`deploy/.env` 或 `services/public-access/.env`）

| 变量 | 示例 | 来源 | 必填 |
| --- | --- | --- | --- |
| `XPAY_OFFER_ID` | `1450000000` | MP 后台 → 支付与交易 → 虚拟支付 → 基本配置 | 是 |
| `XPAY_APP_KEY` | `<现网 AppKey>` | 同上（沙箱另有 AppKey，联调时用沙箱值） | 是 |
| `XPAY_ENV` | `0` | 0=现网，1=沙箱；**生产必须 0** | 否（默认 0） |
| `XPAY_MSG_TOKEN` | 自行生成的随机串 | 与 MP 后台「发货推送配置」的 Token 完全一致 | 是 |
| `XPAY_MSG_AES_KEY` | 43 位字符串 | 与后台 EncodingAESKey 一致 | 安全模式必填 |
| `XPAY_MSG_ENCRYPT` | `aes` | `plaintext` / `compatible` / `aes`；建议安全模式 = `aes` | 否（默认 plaintext） |

补充：

- AppID/AppSecret 复用已有配置（网页管理后台「微信与华为管理员」或 `WECHAT_APP_ID/SECRET`），不会写进小程序。
- 改完 `.env` 后执行 `cd dsh-console/deploy && bash upgrade.sh`（会保留 `.env` 与 data 卷并备份）。
- 服务端只读容器：状态只写 `/app/data`；无需 cron，进程内定时器负责查单兜底。
- 验证配置是否生效：`curl https://dsh.ahwe.top/app-content` 应返回 `payment: { enabled: false, ready: true, tiers: [] }`（`ready:true` 说明凭证已齐）。

## 2. MP 后台配置（按顺序）

1. **开通虚拟支付**：支付与交易 → 虚拟支付 → 开通 → 同意协议 → 填个人资料（身份证/提现账户/支付管理员）→ 提交（约 5 分钟）→ 扫码签约。
2. **记录凭证**：AppID、OfferID、现网 AppKey（基本配置）。AppKey 只填服务端 env。
3. **小程序简称**：左下角图标 → 账号设置 → 基本信息 → 配置简称（iOS 需展示 display name）。
4. **iOS 支付**：虚拟支付 → 基本配置 → 开通苹果 IAP 支付（需先配好简称）。
5. **道具管理**：按档位创建道具，**道具 ID 必须等于 `pub_<days>d`**，价格与小程序档位价格一致（单位分），发布。发布后约 10 分钟生效（错误码 15014）。
   - 道具图：统一使用 `assets/prop-pub-network.png`（200×200，PNG，不带时长标识，任何档位都能用；说明见 [assets/props/README.md](../assets/props/README.md)）。
6. **发货推送配置**：虚拟支付 → 基本配置 → 发货推送配置：
   - URL：`https://dsh.ahwe.top/pay/notify`
   - Token：与 `XPAY_MSG_TOKEN` 一致
   - EncodingAESKey：与 `XPAY_MSG_AES_KEY` 一致
   - 消息加解密方式：安全模式（与服务端 `XPAY_MSG_ENCRYPT=aes` 对应）
   - 数据格式：JSON
   - 点「模拟推送」→ 服务端应返回成功；若失败看服务端日志（验签/AES 配置不一致最常见）
7. **开启道具发货推送**：直购配置页底部「开启道具发货推送」→ 执行测试。
8. **隐私保护指引**：设置 → 功能设置 → 用户隐私保护指引，补充订单/支付信息处理说明（提审前必填）。
9. **客服**：配置小程序客服，供 `open-type="contact"` 使用。

## 2.5 管理员交易记录与退款（2026-11-04 补）

管理员「设置 → 公网权限 → 支付档位」页底部有「交易记录」：

- 汇总：本月笔数 / 金额 / 月限额（10 万元）
- 最近订单列表：时间、订单号、金额、状态
- 每笔订单可点「**核对**」：以微信 query_order 为准显示渠道（order_type=7 即 Apple Pay）、实付、可退余额、微信单号，并自动同步退款扣回天数
- 已发货订单可点「**退款**」：向微信发起 refund_order（仅 Android/鸿蒙；iOS 单会明确提示用户走 App Store）

服务端不依赖消息推送也能闭环：查单兜底发货后调 notify_provide_goods 标记微信侧已发货；每 5 分钟定时对账复查已发货单，发现 left_fee 归零或退款状态自动扣回天数。微信后台「虚拟支付 → 交易订单」按「普通支付 / Apple 支付」渠道切换查看，iOS 单结算约 45–60 天。

## 3. 小程序侧开通（发布新版本后由管理员操作）

> 支付卡片、开关与档位页是本次新增的客户端代码，**首次需要发布包含这些页面的小程序版本**；发布之后，开关与档位的日常调整都不需要再发版。

1. 用管理员微信打开小程序 → 左侧栏 → 设置 → 公网权限 → 「虚拟支付」开关打开。
2. 进入「支付档位」：添加档位（天数 + 价格），保存。
   - 保存成功后提示「请到 MP 后台按 `pub_<days>d` 建道具并发布（约 10 分钟生效）」。
3. 普通用户进入 设置 → 公网访问，应看到支付卡片（天数/价格/购买/退款说明/客服）。
4. 关闭开关后：用户端立即隐藏卡片；已购买天数不受影响；兑换码入口保留。

> 不需要给用户做「绑定登录」：卡片来自公开的 `/app-content`，点购买时才静默 `wx.login`，服务端用同一 openid 直接加天数。

---

## 4. 发布顺序

1. 服务端升级（env + 代码）→ `/app-content` 的 `payment.ready` 为 true
2. MP 后台建道具并发布（等 10 分钟）
3. 管理员在小程序里开关 + 档位
4. 用小额测试道具真单验证（Android 1 分~1 元；iOS ≥1 元）
5. 观察 1~2 天（推送、到账、退款）后再对外宣传

回滚：管理员关闭「虚拟支付」开关即可，兑换码与中继不受影响。

| 官方检查项 | 本项目落点 | 验收方法 |

| iOS 已配置小程序简称 | 第 2 节第 3 步 | 后台显示简称 |
| 消息推送接收已部署 | `/pay/notify`（GET 验证 + POST 推送） | 后台「模拟推送/URL 验证」通过 |
| MP 后台已配置发货推送 URL 并完成测试支付 | 第 2 节第 6~7 步 | 真单支付后服务端订单变为 `delivered` |
| 服务器验签逻辑通过 | `payment.cjs` 签名函数 + 单测向量 | `node --test ... payment.test.cjs` |
| 发货推送幂等（按 wx_order_id/outTradeNo 去重） | `payment.cjs` deliver 幂等分支 | 单测「重复推送只发一次」 |
| 前端 `wx.requestVirtualPayment` 打通并收到推送 | `utils/virtual-pay.js` + 服务端 | 真机支付一笔 |
| 兜底查单逻辑就绪（query_order） | `payment.tick()` + `/pay/query` 兜底 | 关掉推送/断网后仍到账（单测覆盖） |
| 已说明退款规则、结算周期、费率 | 购买页合规文案 | 页面检查 |
| 上线后小额真单验证：支付→推送→发货→账单一致 | 第 6 节 | 逐项记录 |

## 6. 小额真单验证记录（每项打勾并留证）

- [ ] Android：1 分钱测试道具 → 支付成功 → 服务端订单 `delivered` → 账号天数增加
- [ ] Android：支付后立刻杀进程 → 重新进入 → 权益已到账（推送/查单生效）
- [ ] Android：重复支付同一档位 → 生成新单号，天数累加，无重复发货
- [ ] Android：取消支付 → 无订单残留、无报错
- [ ] iOS：微信 8.0.68+ / iOS 15+ → 支付面板显示简称 → ≥1 元支付成功 → 到账
- [ ] iOS：App Store 退款 → 收到 `xpay_refund_notify` → 天数扣回
- [ ] 后台「虚拟支付 → 交易订单」：单号、金额、状态与本地订单一致
- [ ] 月 GMV 统计与实际流水一致（T+3 结算后复核）
- [ ] 关闭开关 → 用户端卡片消失 → 兑换码仍可用
- [ ] 打开开关 → 卡片恢复，价格与后台道具一致（不一致会报 15013）

## 7. 故障排查

| 现象 | 排查 |
| --- | --- |
| 用户看不到卡片 | `/app-content` 的 `payment.enabled/ready/tiers`；管理员开关是否保存成功 |
| 添加档位后返回再进就没了 / 开关自动回弹 | 服务端未升级：`/app-content` 没有 `payment` 字段，`POST /admin/pay/config` 返回 404。先按本手册部署 new public-access 并确认 `curl https://<域名>/app-content` 带 `payment` |
| 下单 503 `PAY_NOT_CONFIGURED` | env 的 OfferID/AppKey 是否生效；AppID/AppSecret 是否在网页后台配置 |
| 下单 403 `PAY_DISABLED` | 开关被关（服务端状态文件） |
| 支付报 15010 | 道具未发布/ID 不匹配（必须是 `pub_<days>d`） |
| 支付报 15013 | 小程序档位价格与后台道具价格不一致 |
| 支付报 15011 | 现网用了 `XPAY_ENV=1`，改 0 |
| 支付报 15014 | 道具刚发布，等约 10 分钟 |
| 支付报 15007 | session_key 过期；客户端会自动重新 `wx.login` 重试一次 |
| 支付成功但天数没到 | 看服务端日志是否收到推送；`/pay/query` 是否触发 query_order；检查 aes/token 配置 |
| 推送一直重试 | 响应格式与推送格式不一致（JSON/XML 必须镜像）或返回了非 0 ErrCode |
| iOS 无法支付 | 微信 <8.0.68 / iOS <15 / 非中国大陆 App Store / 未配简称 |
| 月限额拒单 | `/admin/pay/summary` 看当月 GMV；等下月或改主体 |

## 8. 结算、退款与对账

- Android 等终端：T+3 结算；支付 180 天内退款平台退手续费；可在 MP 后台或 `/admin/pay/refund` 发起。
- iOS：Apple 结算约 45~60 天；开发者无法主动退款，用户向 App Store 申请，退款成功收 `xpay_refund_notify` 后扣回天数。
- 发票：次月 5 号后可申请上月腾讯技术服务费发票。
- 对账频率建议：每周一次订单抽样 + 每月结算后全量核对。
