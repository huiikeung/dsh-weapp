## Scope and sources

Snapshot: current workspace at review time; public reference pinned to commit 3bf35b73325b721f56e5c86ead0a43d8cb0cb6d5 and described by its [README](https://github.com/Clarklevis1995/dsh-mobile/blob/3bf35b73325b721f56e5c86ead0a43d8cb0cb6d5/README.md). ## Protocol and persistence rules

1. Keep Gateway behavior aligned with [miniprogram/utils/protocol.js](../miniprogram/utils/protocol.js) and [native-core protocol/network](../harmonyos/native-core/src/main/ets/protocol/); UI parity must not introduce a second protocol dialect. Use gateway capability/version checks for optional features.
2. PairingPayload.ets validates v2, expiration and candidate endpoints. Current direct transport is WebSocket-based; optional reference RTC is a separate missing capability, not a reason to change existing auth/hello semantics.
3. Credential persistence now uses HarmonyOS AssetStoreKit when available, with legacy Preferences migration and an explicit fallback for devices where the asset service is unavailable. Device-level secure-storage tests are still required before treating trust as fully equivalent to iOS Keychain/Android Keystore.
4. Keep transient projection separate from durable cache. AppStorage session rows do not establish offline history/file cache parity.

## Test and validation gaps

- No tests were discovered under harmonyos/native-app/entry/src/test or harmonyos/native-core/src/test, so native-app/native-core modules have no automated coverage. A clean native-app HAP build succeeded on 2026-11-06; emulator installation was not repeatable because HDC had no confirmed target during the latest check.
- Add native-core parser/codec/request/store tests: malformed/expired pairing payloads; endpoint policy; handshake/auth/token refresh; relay encryption; frame dispatch; duplicate/out-of-order events; reconnect generations; multi-gateway isolation; queue, question and approval transitions.
- Add UI/flow tests for QR/manual pairing, reconnect and host switching; session create/history paging; send/cancel/queue; question/approval decisions; plugin/schedule mutations; and failure/loading/empty/offline states.
- Add device tests for secure credential migration, lifecycle recovery, QR permission denial, microphone/file-picker permissions, interrupted transfers and tablet resizing. Use fixture Gateway credentials only.
- Reference has focused iOS tests including DeepSeekHarnessMobileTests/GatewayProtocolTests.swift, MultiGatewayTests.swift, ChatHistoryCacheTests.swift, and UI tests including DeepSeekHarnessMobileUITests/WorkspaceDrawerUITests.swift. Mirror tested behavior, not Swift test structure.

## Suggested parity order

1. Security and protocol contract: secure credentials, handshake/reconnect correctness, gateway-scoped settings and contract tests.
2. Core conversation: timeline/history fidelity, question/approval actions, queue/stop recovery.
3. Files and voice: native permissions, transfers, previews and explicit privacy/error states.
4. Workspace navigation, plugin detail/configuration and schedule edit/delete.
5. Notifications/lifecycle, offline caches, adaptive layouts, localization and accessibility; then live gateway/device acceptance.
