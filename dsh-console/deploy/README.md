# DSH 公网一键部署

服务端文件现在统一在仓库的 `dsh-console/` 下；本教程位于 `dsh-console/deploy/README.md`。上传时，将本地 `dsh-console/` **里面的内容**放到服务器 `/www/wwwroot/dsh-console/`，不要嵌套成 `/www/wwwroot/dsh-console/dsh-console/`。目录整理不改变服务器路径、Compose 项目名或数据卷。

这个目录把管理后台、WSS relay 和 HTTPS 反向代理放进同一个 Docker Compose 项目。部署后只使用一个域名：

```text
https://你的域名              管理后台
wss://你的域名/relay          小程序和电脑端 relay
```

relay 只转发端到端加密数据；后台负责微信管理员、兑换码和微信账号的公网有效期。用户兑换后扫描**自己电脑的 DSH 插件二维码**，不是连接运营者的 DSH。

**兑换码只管本平台公网中继服务，不限制进入小程序，不修改局域网、直连或自建中继的设备权限。** 公网到期会拒绝连接并断开已有公网连接，局域网仍按原网关权限工作；微信合法域名、系统网络限制仍然适用。公网服务权限与设备配对权限是两件事：有兑换时长也不能访问别人的 DSH。

普通用户不需要在后台添加节点、填写 connector.json 或配置外部授权接口。原有「节点与配对」「限时配对」保留给主动使用这些功能的管理员，不是新用户开通公网的步骤。

## 已部署服务器：上传后直接升级

适用于已经使用本目录统一 Compose 部署的服务器。将本地 dsh-console/ 中更新后的服务端源码覆盖上传至 /www/wwwroot/dsh-console，**保留服务器原 deploy/.env，不上传本机 .env、node_modules、data、relay-state.json、日志或备份，不删除 Docker 数据卷**。不要使用会清除服务器额外文件的同步选项。然后在宝塔终端执行：

~~~bash
cd /www/wwwroot/dsh-console/deploy
bash upgrade.sh
~~~

不用再跑 install.sh、初始化管理后台或重新绑定管理员。升级保留域名、宝塔监听端口、主密钥、管理员、节点、兑换记录及原设备身份；仅在缺少时自动生成内部 relay 鉴权密钥。宝塔仍占用 80/443，原来反代至 127.0.0.1:18080 的配置不变。

脚本先检查四个原数据卷并构建镜像，再短暂停服备份并启动新服务。私有备份保存在 /var/backups/dsh-public/upgrade-时间-随机值/backup.tar.gz；里面包含密钥，不可放网站公开目录或发给别人。构建失败不会停服；停服后失败会尝试重新启动容器，**不会自动回滚镜像**。失败时保留备份并查看日志，不要删卷或重新初始化。需要支持 --wait-timeout 的 Docker Compose Plugin。

重启后网页及小程序可能需要重新登录；连接会重新获取公网票据，但不会清空原设备凭据。旧节点绑定兑换码及历史数据按旧协议保留，不能自动改成全平台码；新生成兑换码默认是账号公网服务。

**这次升级须配套更新小程序和电脑插件连接器**：服务端升级不会自动发布小程序，也无法远程更新用户电脑插件。旧公网客户端缺少授权票据会被拒绝，旧连接器会明确提示升级。请先准备好下述兼容版本，再安排维护窗口；局域网不依赖这些公网升级。

**订阅消息模板 ID 只在小程序端配置**（`miniprogram/utils/notify-config.js`）；小程序申请票据时会把模板 ID 一起提交，服务端按票据里的 ID 发送，服务器 `.env` 无需填写模板 ID。换模板后重新发布小程序即可。

## 用户如何开通和连接自己的 DSH

1. 运营者在网页配置小程序 AppID/AppSecret，核实并绑定微信管理员。管理员生成「鲸尾公网服务」兑换码，支持 3 天、7 天、30 天、半年（180 天）、1 年（365 天），与小程序管理员页面同步。
2. 用户进入小程序「设置 → 公网访问」，用自己的微信兑换。未到期从原截止时间续期，已到期从兑换时开始。每账号每码仅一次；兑换码本身 30 天内有效，可设置 1/5/20 人使用。停用兑换码只阻止后续兑换，不撤回已兑换时长。
3. 用户在**自己的电脑**安装兼容版 dsh-plugin-weapp-gateway，开启移动网关，选择「鲸尾公网 · 小程序」。本项目安装器已内置公网入口，用户无需填写域名；面板显示「鲸尾公网服务」及设备 ID。
4. 在插件生成公网配对二维码，小程序「节点 → 扫码/输入配对信息」连接。插件的配对码仍负责设备授权，兑换码不代替配对码。
5. 公网到期仅公网连接停止；续期后可以重新连接，不需要重新授予局域网权限。已绑定的微信管理员当前自动拥有公网服务权限，没有兑换到期限制；移除管理员后按普通账号有效期重新校验。

### 已安装旧插件：一次性升级内置连接器

旧插件不能只靠服务器升级获得安全配对能力。在**运行 DSH 的电脑**保留本仓库 dsh-console/relay 文件夹，然后执行（替换为这台电脑上的真实绝对路径）：

~~~bash
node /绝对路径/dsh-weapp/dsh-console/relay/install-plugin-connector.cjs /绝对路径/已安装的/dsh-plugin-weapp-gateway
~~~

安装器检查插件名称及源码特征，备份并更新 relay/agent-connector.js；对 lib/client.js 和 lib/relay-connector.mjs 仅应用可识别的局部修改，保留其余插件功能。全部源码检查通过后才写入，重复执行不会重复改动或备份。不修改网关入口、身份、设备凭据，不自动重启 DSH。等待正在运行的任务完成后正常重启 DSH、刷新插件面板，再生成新二维码连接。它不需要 connector.json，也不是旧文档的「限时配对扩展」。如插件管理器后来覆盖了这些文件，需要重新运行安装器或发布集成此连接器的新版插件。备份路径会在命令输出显示；不兼容版本会停止而不是强行覆盖。

**注意实际加载目录**：desktop profile 可能同时存在 local-plugins/dsh-plugin-weapp-gateway（源码）和 node_modules/dsh-plugin-weapp-gateway（运行副本），两者不一定是软链接。请更新实际运行副本；开发本地插件时也同步源码，避免下次安装覆盖。此 Mac 的运行副本命令为：

~~~bash
node /Users/0the/Downloads/dsh-weapp/dsh-console/relay/install-plugin-connector.cjs /Users/0the/.dsh/profiles/desktop/node_modules/dsh-plugin-weapp-gateway
~~~

内置入口会将原 relay.ahwe.top 自动迁移至当前公网服务，自建第三方中继配置保持不变。此前扫码保存了旧入口的手机，需更新小程序并重新扫描新二维码；不必删除电脑上的可信设备。更换运营域名属于发布配置：同时更新连接器、监督进程和小程序 access-config.js，不能只改网页反代。

隐藏面板域名仅用于简化界面，不是安全隔离：二维码协议和网络请求仍包含真实地址。防护依赖 HTTPS、服务端公网时长校验、设备配对认证及端到端加密，不应把隐藏域名当作防攻击措施。

### 后台高级功能

网页侧栏「高级功能」默认收起，包含「托管节点与配对」「限时设备配对」。小程序设置已移除管理员限时配对入口，普通「节点 → 添加节点 → 扫码/输入」保留。高级接口和历史记录仅兼容托管电脑的旧场景，不是用户开通公网的前置步骤。

## 本次更新：管理员设备 ID、兑换码与分享活动

### 开发者公告、客服与分享开关

网页「开发者公告」及小程序「设置 → 管理员 → 发布公告」可发布、编辑、删除同一份公告。支持 60 字标题、3000 字纯文本正文，最多 100 条；按发布时间倒序，两端同时编辑会提示冲突。普通用户在「设置 → 关于 → 开发者公告」查看和展开，不要求连接电脑或购买公网服务。公告默认空，不附带虚构版本公告。

「关于」内公告下面是微信原生「联系客服」。运营者须在微信公众平台为本小程序启用客服并添加客服人员；没有配置时不能声称已有人接待。客服消息由微信处理，不会转成后台站内工单。正式发布前用真机验证客服入口。

网页「分享活动」及小程序管理员设置中的「分享活动」使用同一个持久化开关。关闭会暂停活动并隐藏公网分享按钮；设置页重新进入、打开公网面板或手动重试同步时更新，不是实时推送。分享活动页重新进入或刷新后也隐藏转发按钮和原生分享菜单。旧活动链接不再产生新奖励；原兑换有效期、已获奖励和局域网连接不变。其他普通页面的应用介绍分享不属于奖励活动。

网页「微信与管理员」统一只通过 WX- 开头的设备ID绑定；已移除旧绑定码及直接填写 OpenID 的界面。旧管理员权限不丢失，本人打开新版小程序设置后，网页刷新即可显示对应 WX- ID。历史兼容接口仍保留。小程序公网面板只显示该设备ID，不再混放电脑节点ID；宽度不足时末尾省略，复制仍是完整ID。

上传时必须包含新增的 announcements.cjs、notifications.cjs，并更新 web。执行 bash upgrade.sh 后还需重新编译发布小程序；服务端更新不会自动替换手机上的旧包。

本次服务端代码有变更，需上传完整源码后运行上面的 bash upgrade.sh；不需要重装或重新初始化。Dockerfile 已包含 engagement.cjs、announcements.cjs 和 notifications.cjs。不要只上传 web 文件夹。小程序还需单独编译、预览、审核发布；服务器升级不会改变用户手机上的旧包。

### 输入设备 ID 绑定微信管理员

1. 本人打开新版小程序「设置 → 公网访问」，复制「设备ID」（WX- 开头）。未开通公网、没有连接电脑也能获取。
2. 网页「微信与管理员 → 通过设备 ID 绑定管理员」，填写 ID 和备注，核实本人后确认。
3. 返回小程序重新进入设置，服务端重新验证微信身份，只有管理员显示「微信身份」和「兑换码管理」。普通用户不显示这个模块。
4. 网页移除管理员后，下一次请求立即失去管理权限；页面回到前台会重新同步。

WX- ID 是服务端依据微信登录核验结果生成的**账号标识**，不是手机硬件号，也不是 DSH 插件节点 UUID。同一微信重装/清缓存后 ID 不变；不同微信不能提交别人的 ID 伪造身份。绑定要求该微信在最近 24 小时内完成身份核验。仅持有 ID 不会自动获得权限，必须由已登录的网页管理员批准。管理员绑定不是微信公众平台管理员名单的自动读取。

### 兑换码复制与删除

网页和小程序的「最近生成」现在都提供复制、停用、删除，新生成结果也有复制/删除。删除会停止后续兑换并从列表移除；已兑换时长不变，必要审计记录保留。

新版兑换码以 AES-256-GCM 加密保存，复制接口每次校验管理员权限。ACCESS_MASTER_KEY 必须与 data 一起备份；更换/丢失主密钥后不能解密。旧版仅保存摘要的码不能恢复完整原文，复制时会明确提示，可删除并生成新码；不能凭空补回旧码。

### 分享活动配置与验收

分享活动**默认暂停**，首次上线前由运营者核对微信最新运营规范、分享激励限制和隐私告知，再在网页「分享活动」启用。这里没有保证此激励方案能通过微信审核，也没有绕过平台限制。

默认阶梯按**每一位新增有效好友**计算：第 1–10 位每人 3 天，第 11–15 位每人 7 天，第 16 位起每人 30 天；不追溯补发，门槛和天数可在网页调整。更高未指定阶梯不擅自追加。修改影响后续好友奖励；朋友圈按登记时的奖励天数。

小程序「公网访问 → 分享」打开底部弹窗；「活动规则」进入鲸尾分享助手。好友/群聊收到的是活动链接，**不是设备配对邀请**。好友打开后完成微信登录并点击「确认有效打开」才计奖。同一 OpenID 全活动只计一次，自己打开不计奖；并发请求和服务重启不重复发奖。不同微信不等于不同硬件/自然人，不能声称完全防刷，运营需评估小号滥用和成本。

朋友圈没有可用的“分享保留一天”自动证明，因此采用诚实的人工流程：

1. 在活动页使用微信右上角菜单分享到朋友圈，再「登记今日截图」。
2. **从服务器收到首次截图起**保留满 24 小时，回活动页刷新并「提交保留截图」。提前提交会被服务端拒绝。
3. 网页「分享活动 → 朋友圈凭证审核」查看两张截图，核实后通过或拒绝。通过才增加默认 3 天，每个微信按北京时间每天登记一次。点击分享、上传第一张图都不等于成功。
4. 截图不能技术证明连续保留；审核者需人工甄别，系统不宣称绝对防伪。活动暂停会阻止新增/复核提交；已进入待审的记录仍可处理。

仅支持 330KB 内 PNG/JPEG 截图。上传前有隐私确认，提醒遮挡无关信息；仅网页管理员能读取，列表不批量加载图片。决定审核后删除两张图；未处理的截图在登记 7 天后自动过期，服务运行时每分钟清理、重启时补清理。奖励账本和去重标识保留以防重复领奖。备份可能包含旧凭证，运营者也需设置私有备份保留/删除策略，并更新真实隐私政策与微信后台隐私声明。

本地自动化覆盖设备 ID 提权拦截、复制/删除同步、加密后重启恢复、10/11/15/16 阶梯、并发去重、朋友圈 24 小时校验/审核/截图清理。正式发布前还必须用**两个真实微信账号**验证群聊卡片打开、朋友圈菜单、相册隐私授权和后台审核；本地编译及模拟登录不能替代真机验证。

新连接器把用户的设备配对凭据通过端到端加密通道交给自己的 DSH；必须等网关明确确认 authenticated: true 才放行业务消息，即使本地开启调试免认证也不会放过无效公网设备凭据。不会因为用户买了公网时长就自动给其授予电脑访问权限，也不会改动原局域网认证设置。

## 服务器首次安装

要求：一台能运行 Docker 的 Linux 服务器，域名 A/AAAA 记录指向服务器，安全组/防火墙放行 TCP 80 和 443。

宝塔服务器只需上传本地 `dsh-console/` 里面的服务端源码到 `/www/wwwroot/dsh-console`，无需上传小程序。目标目录必须直接包含 `deploy`、`services/public-access` 和 `relay`：

```text
/www/wwwroot/dsh-console/
├── deploy/
├── services/public-access/
└── relay/
```

在宝塔终端执行：

```bash
cd /www/wwwroot/dsh-console/deploy
chmod +x install.sh migrate.sh
./install.sh --baota
```

脚本会询问一个域名，自动生成 `deploy/.env` 中的密钥，构建并启动三个容器。`--baota` 模式不会占用宿主机 80/443，只监听本机 `127.0.0.1:18080`；宝塔网站反向代理到这个地址即可。不要再单独部署旧 relay、systemd 或宝塔 Node 项目。

宝塔网站的反向代理目标填写：

```text
http://127.0.0.1:18080
```

宝塔反向代理还要确认：代理目录为 `/`、发送域名为你的公网域名、关闭代理缓存、开启 WebSocket；不要让站点原有的静态 `root/try_files` 规则截走 `/console/*` 和 `/relay/*`。宝塔负责 80/443、SSL 和域名；小程序仍使用 `wss://你的域名/relay`。

先在服务器本机检查内部页面，下面应返回 `HTTP/1.1 200` 和管理台 HTML（把域名替换成你的真实域名）：

```bash
cd /www/wwwroot/dsh-console/deploy
docker compose ps
curl -i -H 'Host: 你的域名' http://127.0.0.1:18080/
docker compose logs --tail=80 caddy console
```

本机返回 200 但域名空白，问题就在宝塔站点反代规则；本机也失败，则先看容器日志并执行 `./install.sh --baota` 重新应用配置。

如果刚才已经运行过不带参数的命令并提示 443 被占用，先执行下面的命令（不会删除数据卷），再用宝塔模式重启：

```bash
cd /www/wwwroot/dsh-console/deploy
docker compose down
./install.sh --baota
```

初始化时打开脚本输出的管理后台地址。页面要求「初始密钥」时，在服务器执行下面的命令查看 `CONSOLE_SETUP_TOKEN`：

```bash
cd /www/wwwroot/dsh-console/deploy
grep '^CONSOLE_SETUP_TOKEN=' .env
```

把等号后面的完整内容填入页面，再设置一个至少 12 位的管理密码。不要填写 `ACCESS_MASTER_KEY`，也不要把两个密钥发给别人。初始化完成后，初始密钥不能替代管理密码登录。电脑端 connector 的 relay 地址填写：

```text
wss://你的域名/relay
```

微信后台 request 合法域名填写 https://你的域名，socket 合法域名填写 wss://你的域名（合法域名列表不填写 /relay 路径）。插件中继地址使用 wss://你的域名/relay。小程序 utils/access-config.js 的 baseUrl 使用 HTTPS 根地址；更新后另外编译发布。电脑端按本页「用户如何开通」操作，不需要旧版后台节点连接器。

## 换服务器

旧服务器执行：

```bash
cd /www/wwwroot/dsh-console/deploy
./migrate.sh backup /tmp/dsh-public-backup.tar.gz
```

备份文件包含管理台状态、relay 身份/配对状态、HTTPS 证书配置和 `.env`，必须用安全方式传到新服务器，不能发到聊天或提交 Git。

新服务器准备同一份代码后：

```bash
cd /www/wwwroot/dsh-console/deploy
chmod +x install.sh migrate.sh
./migrate.sh restore /绝对路径/dsh-public-backup.tar.gz
```

恢复脚本会要求输入 `RESTORE`，然后覆盖四个数据卷并启动服务。恢复命令会从备份的 `.env` 读取域名和密钥，因此域名不变时，小程序和电脑端无需重新配置；如果更换域名，先修改 DNS 和 `.env` 的 `PUBLIC_DOMAIN`、`CONSOLE_ORIGIN`，再恢复并重新提交微信合法域名。

如果你现在运行的是旧版独立 relay，先把旧服务器上的 `relay-state.json` 复制到新服务器，再执行：

```bash
./migrate.sh import-relay-state /绝对路径/relay-state.json
```

确认 `wss://你的域名/relay` 和小程序都正常后，再停止旧 relay。不要让新旧两个 relay 同时使用同一个域名或同一个节点。
导入会保留 relay 的节点身份和访问状态；但旧二维码里写着旧 relay 地址，域名或路径变更后需要在小程序更新主机地址，或重新生成一次配对信息。

## 日常命令

```bash
cd /www/wwwroot/dsh-console/deploy
docker compose ps
docker compose logs -f --tail=100
docker compose restart
bash upgrade.sh
```

不要执行 `docker compose down -v`，否则会删除管理账号、节点和 relay 配对状态。
